# DeviceDNA: Comprehensive Project Context for AI Assistants

This document serves as a complete brain-dump of the DeviceDNA project. It is designed to be fed into any AI assistant to instantly bring it up to speed on the architecture, current state, frontend pages, and (most importantly) the technical debt, missing features, and future roadmap.

## 1. Project Overview & Architecture
**DeviceDNA** is a software-defined cybersecurity intelligence platform for IoT networks. It uses a multi-dimensional ML ensemble to assign real-time trust scores (0–100) to devices, detecting anomalies and executing autonomous network responses.

### Tech Stack
*   **Backend**: Python 3.11, FastAPI, Socket.IO (ASGI), PyTorch, Scikit-Learn.
*   **Frontend**: Next.js 14 (App Router), React, Tailwind CSS, Framer Motion, Recharts, Socket.IO Client.
*   **Infrastructure (Docker Compose)**: PostgreSQL 16 (Relational state & Alerts), InfluxDB 2.7 (Time-series telemetry), Redis 7 (Fast caching, PubSub, TTL state), Kafka + Zookeeper (High-throughput message broker).
*   **Simulator**: Custom Python script generating synthetic network flows for 50 devices across 6 classes (camera, sensor, thermostat, access_control, medical, industrial).

## 2. Machine Learning Ensemble (The 5 Pillars)
The `TrustScoreEngine` in `backend/app/services/trust_engine.py` aggregates 5 distinct algorithmic pillars:
1.  **VAE Digital Twin (Reconstruction)**: 14-dim → 32 → 16 latent space autoencoder. Detects deviation from normal baseline.
2.  **Isolation Forest (Structural)**: Scikit-learn isolation forests trained per device class.
3.  **LSTM (Sequence Forecasting)**: Predicts the next feature vector based on a rolling window of 12 steps. Detects temporal anomalies.
4.  **GNN / GraphSAGE (Spatial/Lateral)**: Detects anomalous communication edges by building dynamic graphs of co-evaluated devices.
5.  **CUSUM (Statistical Drift)**: Tracks cumulative sum of minor deviations to catch slow, stealthy data exfiltration.

**In addition to ML, the trust engine includes:**
*   **Policy Conformance**: Deterministic rules (e.g., "Medical devices cannot talk to external IPs").
*   **Peer Consensus**: Cross-references a dropping trust score against other devices of the same class.

## 3. Frontend Architecture & Pages
The UI is a dark-themed, premium "glassmorphism" SOC dashboard.

*   `app/page.tsx`: Landing page with an ambient video background, animated KPIs, and a mock terminal.
*   `app/dashboard/page.tsx`: Main SOC Overview. Includes top KPIs, a D3-based Network Topology Map, a Sparkline drawer for clicking nodes, a Trust Score Timeline, and a live WebSocket event log.
*   `app/dashboard/node/[id]/page.tsx`: Deep-dive into a specific device. Shows a radial trust score gauge, a 24-hour history line chart, a 7-day CUSUM Drift Heatmap, and a SHAP Threat Intelligence Brief. Contains the Autonomous Response Status Panel.
*   `app/dashboard/alerts/page.tsx`: Historical and real-time feed of alerts triggered by the engine.
*   `app/dashboard/policies/page.tsx`: UI for the NLP Policy engine (translating English to firewall rules using BERT).
*   `app/dashboard/predict/page.tsx`: Displays LSTM forecasting variance and the CUSUM Drift Heatmap.
*   `app/dashboard/replay/page.tsx`: A forensic timeline scrub tool for re-evaluating historical incident telemetry vectors.

## 4. CRITICAL: What is Fake, Missing, or Needs Fixing

### A. Data Collection & Model Training (The Biggest Gap)
*   **NO REAL DATASET**: We have **not** collected any real-world PCAP or IoT dataset. The system currently runs entirely on synthetic dummy data generated by `backend/simulator/traffic_generator.py`. 
*   **DUMMY TRAINING**: The models in `backend/models_trained/` were generated by running the `backend/training/train_*.py` scripts against the synthetic data simulator for a few epochs. 
*   **TO-DO**: We desperately need to ingest a real dataset (like IoT-23 or UNSW-NB15), extract the 14-dim feature vectors, and retrain the VAE, IF, LSTM, and GNN models properly.

### B. Phase 2: Autonomous Response Engine (Incomplete)
*   **Current State**: We have a basic `ResponseEngine` (`response_engine.py`) that sets Redis TTL keys (`response:isolated:{id}`) and emits WebSockets when scores drop below hardcoded thresholds (< 20, < 40).
*   **Missing (Phase 2 PRD)**: 
    *   **MQTT Dispatch**: The backend needs to actually publish MQTT JSON commands to physical ESP32 hardware to click relays.
    *   **ESP32 Firmware**: We need the Arduino C++ code to receive MQTT commands and actuate hardware limits.
    *   **5-Tier Risk Classifier & Trust Decay**: We need to implement the mathematical decay multiplier based on 60-minute event history, rather than static `< 20` checks.
    *   **Human-in-the-Loop (HITL)**: Tiers 4/5 should enter a pending queue requiring an operator to click "Approve" in the dashboard.
    *   **Recovery Mode**: Devices should slowly regain trust after 5-10 minutes of clean behavior.

### C. Backend & API Debt
*   **InfluxDB Persistence Bug**: In `trust_engine.py`, the code says `# NOTE: Missing feature - Persisting this score to InfluxDB`, but there is a `try/except` block right below it attempting to write it. We need to verify if historical graphs actually pull from InfluxDB properly.
*   **Topology Graph Data**: The frontend `NetworkTopologyMap.tsx` might still be using some mocked edges. It needs to accurately reflect the live Kafka flow `src_ip` to `dst_ip` data.
*   **GNN Training**: The `train_gnn.py` script is highly experimental. Real graph edges based on network flows need to be formalized.

### D. Frontend Debt
*   The `/dashboard/topology` full-page route exists but needs to be heavily polished.
*   Alert resolution: Clicking "Resolve" on the frontend needs to accurately clear the alert from PostgreSQL and update the Zustand store / UI instantly without requiring a page reload.

## Summary for AI Prompting
When working on this codebase, remember that the **data pipeline (Kafka -> Feature Extraction -> ML Scoring -> WebSocket -> React)** works, but the **underlying data is synthetic**, and the **hardware response loop is incomplete**.
